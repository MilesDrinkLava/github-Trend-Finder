## 已修复

| 严重度 | 问题与触发方式 | 修复 |
|---|---|---|
| 高 | 预览服务静态根目录为仓库根，`/token.txt`、`/.git/config` 可被下载 | 只暴露 `dist/`，敏感文件路径回归确认 404 |
| 高 | 缓存未区分凭据；换 token 后可能复用此前账号可见的仓库结果 | Python 持久缓存使用 SHA-256 凭据指纹，Rust 内存缓存使用凭据散列，缓存键不含原始 token |
| 中 | 先取 1 条，再请求 30 条，仍复用只有 1 条的缓存 | 缓存键纳入 limit；排序、过滤和凭据一并隔离 |
| 中 | Python 离线回退忽略 `archived:false`、语言和 star 限定 | 归档过滤在本地执行；未实现的限定符明确返回错误，不返回未过滤结果 |
| 中 | 搜索和发现请求独立，快输和切榜没有全局节流 | Rust 共享异步队列；匿名 6.2 秒 / 认证 2.1 秒最小间隔；遵循 Retry-After / reset 冷却，跳过排队的过期查询 |
| 中 | 旧请求的错误、finally 或同文查询结果可以覆盖当前状态 | 前端使用递增请求序号；清空输入立即失效，旧请求不能关掉新请求的 loading |
| 中 | 输入法组字过程中触发搜索，浪费配额 | compositionstart / compositionend 期间暂停输入搜索，完成后统一防抖 |
| 中 | 热榜前端缓存永不过期；旧热榜错误覆盖新筛选 | 30 分钟 TTL 和请求序号；应用启动不再预先请求隐藏热榜 |
| 中 | `C++` / `C#` / `.NET` 被拆成 `c` / `net` | 保留符号并映射到 cpp / csharp / dotnet，另补 13 条技术名别名 |
| 中 | “识别图片”被直接塌缩为 OCR | OCR 要求文字语义；图片识别保留 image recognition，物体识别使用 object detection |
| 中 | “支持中文”被当作填充词丢弃 | 保留 chinese，避免悄悄放宽用户明确提出的条件 |
| 中 | 已知英文词从不进入子串索引；两字中文无法用 trigram 匹配 | 合并主索引与子串索引，增加两字未知中文的受限扫描兜底；保持有效主结果 |
| 低 | Apache / BSD 等许可证大写比较失配；MPL 被误列为宽松许可证 | 对照集统一大写，移除 MPL；同时修复无时区日期和未来日期处理 |
| 低 | 损坏缓存 JSON 直接报错；相对数据库文件名或 `:memory:` 连接失败 | 损坏缓存视为未命中；数据库父路径按绝对路径创建 |
| 低 | 翻译关闭后在途译文仍写回 | 翻译回写检查开关及当前代次，关闭时还原英文 |

## 词库

- 从 226 个概念 / 501 条英文术语扩展到 380 / 788。
- 补齐开发、AI、媒体、文件、网络、安全、效率等完整词组及常见口语别名。
- 增加 13 条 ASCII 技术名别名、157 个常见字形对照项（其中包含不变字），支持全角 ASCII / 空格。
- 统一 Python 与 Rust 的字形归一化、最长匹配和概念组合规则；未识别中文仍作为诊断输出保留。
- `lexicon.py` 是唯一来源，`export_lexicon.py --check` 检测 JSON 过期，构建脚本先检查。

## 验证

- 51 条手工查询由 Python 与 Rust 共同执行，包含容易混淆的反例；逐条验证 380 个概念能被完整识别。
- Python 回归覆盖缓存条数与凭据隔离、损坏缓存、离线过滤、子串 / 两字中文、预览目录隔离。
- Node 回归模拟旧请求失败、同文请求乱序与清空输入，检查所有内联脚本语法。
- Rust 核心集成测试运行词库、限流响应头和 URL 边界；通过 `cargo check --locked` 与格式检查。
- 这些检查不证明实时 GitHub 召回质量已经提升；新增词仍需真实用户查询评测。

## 尚存限制

- 本机 PAT 仍为配置文件明文存储；未引入 Windows Credential Manager / DPAPI。token、数据库、日志均不纳入提交。
- Python CLI 仍依赖服务端限流反馈，新的共享队列用于桌面端；并不协调多个进程或同账号的其他客户端。
- 离线排序仍是实验性质。主检索沿用 GitHub best match；trigram 支持子串，不支持编辑距离。
- 词库不是通用翻译系统，常见繁体对照不是完整繁简转换；否定条件和复杂自然语言约束尚无完整解析。
- 开发预览的发现页仍为演示数据；真实发现请求在桌面版执行。
